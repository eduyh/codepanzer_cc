# CodePanzer.py - Code Your Tank, Command the Arena.
**Version: v1.5.19**

**CodePanzer.py** は、2D グリッド上に命令チップを並べて戦車の自律 AI を設計し、リアルタイムに対戦・検証できるプログラミング戦車バトルシミュレータです。

グリッド形式のフローチャートと **Python 構文**（`if / else`、`for`、`while`、変数演算、`def sub_a():` サブルーチン、`print()` デバッグなど）がリアルタイムに双方向連動しており、プログラミングの基礎から、基本的な自律ロボット制御アルゴリズムの構築までを直感的に学べます。

学習カリキュラムは **1単元あたり約60分** のペースで取り組めるよう設計されており、基礎的なロボット戦車の動作を学ぶ **「課題学習」** と、ゲームに対応した戦車 AI の実戦的な組み方や、兵装の運用を学ぶ **「開発訓練」** の各4単元（1コース約240分・合計8単元 約480分）で構成されています。大学生の能力であれば、1コマにつき2単元（各コース2コマ・合計4コマ）づつ進めることも可能だと思います。

## 1. 起動方法と動作環境

### 方法 A: ポータブル版をブラウザで直接起動（推奨・インストール不要）
Node.js や Python の環境構築は不要で、オフラインの Web ブラウザだけでそのまま動作します。

1. `dist/index.html` または配布アーカイブ（`vstank-portable.zip`）を展開したフォルダ内の **`index.html`** をダブルクリックするか、Web ブラウザへドラッグ＆ドロップします。
2. 対応ブラウザ: Google Chrome / Microsoft Edge / Safari / Firefox（WebGL 対応環境。非対応時は 2D Canvas へ自動フォールバックします）

### 方法 B: 開発環境から起動（ソースコード編集・テスト）
Node.js (v18 以上推奨) 環境でリポジトリをクローンして実行します。

```bash
# 依存パッケージのインストール
npm install

# 開発サーバーの起動
npm run dev

# ユニットテストの実行 (Vitest)
npm test

# 型チェックと本番ビルド
npm run build

# 単一 HTML + tanks/ フォルダ一式のポータブル ZIP パッケージを生成
npm run package
```

## 2. システムと動作の仕組み

### 2Dグリッドプログラミング × Python コードの双方向連携
- **4方向隣接接続**: グリッド内の各ブロックから上下左右に隣接するマスへ接続線（`next` / `T:True / then` / `F:False / else`）をつなぎ、思考フローを組み立てます（Python ソースの直接編集からの変換時は、離れた接続先を空きマスのワイヤーで自動補完します）。
- **CPU グリッドサイズ**: 入門向けの **4×4**（最大16ブロック / 16 step/t）から **6×6**（24 step/t）、**8×8**（48 step/t）、大規模アルゴリズム向けの **12×12**（96 step/t）まで選択できます（スマホレイアウト時は 4×4〜8×8 に対応）。
- **チップ｜コード切替と武装カテゴリ**: 右ペインの **「チップ｜コード」** 切り替えにより、配置済みグリッドに対応する Python コードのリアルタイム表示や、**「直接編集・貼付」** によるコードからの自動変換・盤面反映が可能です。主砲 (`fire_main()`) と Special 兵装 (`use_sp()`) は **武装 (Weapon)** カテゴリにまとめられており、インスペクタ内の各チップ解説は必要に応じて開閉（標準では折りたたみ）できます。
- **学習ガイド**: 盤面・パレットのチップまたは Python コードの各行にカーソルを合わせると、対応する Python 構文と文法解説を確認できます（折りたたみ可能。**課題学習** モードでは初期状態で展開されます）。
- **デバッグ支援・画面レイアウト**: 各チップの `print()` デバッグ出力を有効にすると、実行中に戦車の頭上へ吹き出しでメッセージや変数値が表示されます。また上部バーから画面全体の文字サイズ（**標準 / 大 / 特大**）や表示レイアウト（**スマホ / コード / 標準**）を切り替えられます。

### ユーザー管理・データ互換性・環境バックアップとリストア
- **ユーザー識別と文字数上限**: 上部バー右端のハンバーガーメニューから **ユーザーネーム（最大8文字）** を登録でき、環境ごとに **ユーザー UUID（自動発行・読み取り専用）** が割り当てられます。自機名（`tank_name`）は最大16文字に設定されており、インポート時に上限を超えている場合は自動で切り捨てて安全に取り込みます。
- **作成者・バージョン情報の保持と自動補正**: 書き出される Python ソース（`tank_name`, `author_name`, `author_uuid`, `game_version`）、`.vstank.json`、シェアコード（`VST1-...`）には作成者識別情報とセマンティックバージョンが記録されます。読み込み時にはゲートキーパー処理により廃止チップの移行や範囲外パラメータの正規化を行うほか、現在のアプリより新しいバージョンで作られたデータの場合も検知して通知します。
- **環境のバックアップ＆リストア**: 同じくハンバーガーメニュー内で、課題学習・開発訓練のクリア状況や保存済み機体数を確認できるほか、ユーザー設定・開発中自機・保存済み機体ライブラリ・各モードのクリア状況・文字サイズ設定を一括で **環境ダンプコード（`VSE1-...`）** または **JSON ファイル（`codepanzer_env_*.json`）** として書き出し・上書き復元できます。

### シミュレーション・機体仕様
シミュレーションは基本 **20 TPS（1秒 = 20 Tick `t`）** で進行し、再生速度（`0.25x` `slow` 〜 `2.0x` `rapid`）・一時停止・1 Tick コマ送りに対応しています。

| 要素 | 仕様・動作 |
| :--- | :--- |
| **3軸独立制御** | **車体 (Body)**・**砲塔 (Turret)**・**レーダー (Radar)** をそれぞれ独立して旋回可能 |
| **座標モード** | **相対座標 (`relative`)**（自機・砲塔正面を `0°` とする相対角）と **絶対座標 (`absolute`)**（北 `0°` / 東 `90°` / 南 `180°` / 西 `270°`）を切替可能 |
| **方向別装甲** | 砲弾の着弾方向に応じてダメージ倍率が変化（**正面 `0.8x`** / **側面 `1.0x`** / **背面 `1.25x`**） |
| **シャシーと積載量** | **軽量** (`HP90 / 積載76t`)・**標準** (`HP130 / 積載100t`)・**重量** (`HP190 / 積載135t`) に加え、砲塔固定＆主砲冷却+20%の **超重** (`HP210 / 積載160t`) を選択可能。総重量超過時は移動・旋回速度にペナルティ |
| **レーダー視界と記憶** | **広角 (`120° / 480px`)**・**標準 (`50° / 820px`)**・**狭角 (`22° / 1550px`)** の3種。視界外に出ると **28t** 後に捕捉記憶が消滅（古い記憶では偏差射撃の精度が減衰）。`under_lock()` で被ロック、`hit_from()` で被弾方向を検知可能 |
| **近接・衝突処理** | `proximity_near()` で全周の壁・障害物・他戦車をスキャン（接近・左右比較・左手法/右手法対応）。壁接触時は壁沿いに滑走して法線速度のみでダメージが発生し、車両衝突時は実重量比・運動量に応じた弾き返し（膠着時は段階的な引き剥がしと接線スリップ）により重量級でも側面・背面への高速衝突時は車体角が大きく振られます |
| **主砲 (Main Gun)** | **軽量砲** (`P=0.5/1.0/1.5`)・**標準砲** (`P=1.0/1.8/2.5`)・**重量砲** (`P=2.0/2.5/3.0`) の3種に対し、`fire_main(power="fast" \| "normal" \| "heavy")` の **速弱 / 標準 / 遅強** の3段階を指定（実効威力・弾速・冷却Tickは装備構成に応じて自動算出） |
| **Special (SP) 兵装** | **装備なし** (`0t`)・**煙幕**（視界遮断100t・3回 / `9t`）・**緊急ブースト**（50t・速度/旋回1.7倍 3回 / `10t`）・**デコイ**（HP25おとり150t・3回 / `11t`）・**地雷**（5発 / `12t`）・**バリア**（120t・被ダメ60%減 3回 / `15t`）・**誘導ミサイル**（4発 / `16t`） |
| **戦場サイズ** | **極小 (`600×480`)**・**小 (`840×660`)**・**中 (`1100×860`)**・**大 (`1400×1100`)** の4段階 |
| **対戦・勝敗判定** | テストグラウンドでは **最大8台**（スマホレイアウト時は **最大4台**）のバトルロイヤルおよび **1 vs 多のチームバトル** に対応。敵機の自滅やタイムアウト時は誤って撃破勝利にならず **引き分け (`DRAW`)** として厳密に判定 |

## 3. カリキュラム構成（課題学習・開発訓練・機体開発）

上部モード切替から **「課題学習」「開発訓練」「機体開発」** の 3つの学習・開発モードを切り替えられます。課題学習・開発訓練ではステージごとに必要最小限のチップがパレットに表示され（必要に応じて「全チップを表示」も可能）、「ヒント」や「模範解答」ボタンでいつでも参照できます。

| モード | 構成 | 主な内容 |
| :--- | :---: | :--- |
| **課題学習** | 全4回・24ミッション | 2パターン自動検証やチェックポイント走破を通じて、順次処理・条件分岐・変数/ループ・サブルーチン・絶対座標まで段階的に習得 |
| **開発訓練** | 全4部・19ステージ | **`4×4` 基準・1ステージ1要素** の段階構成で、索敵射撃・引き撃ち・SP兵装戦術・1 vs 2 連携戦まで対人戦術を習得 |
| **機体開発** | フリー対戦・検証 | 自作機体と付属/外部戦車（最大8台）を組み合わせてバトルロイヤルやチームバトルで自由にテスト |

### 課題学習（全4回・24ミッション）
基礎構文から自律アルゴリズムまで、複数パターンの自動検証やチェックポイント走破を通じて段階的に習得します。

| 回 | テーマ | ミッション | 主な学習内容 |
| :---: | :--- | :---: | :--- |
| **第1回** | 順次処理・`for`文・砲塔操作 | `1-1` 〜 `1-6` | 直進・停止 `stop()`・`turn_body(wait=True)`・`time.sleep()`・`for i in range(4):`・砲塔独立操作・固定砲塔 (`destroyer`) |
| **第2回** | センサー・条件分岐 (`if/elif/else`) | `2-1` 〜 `2-6` | 前方壁回避・色タイル分岐 (`on_tile(..., edge=True)`)・3色多段分岐・`proximity(approaching)` スラローム・ミッション状態切替・左手法 (`left_open`) 迷路踏破 |
| **第3回** | 変数・乱数・状態遷移・`while`文 | `3-1` 〜 `3-6` | カウンタ `a += 1` (`a == 3`)・状態遷移 (`mode = 0 / 1`)・`while not enemy_detected():` 全方位索敵・偏差予測 (`lead="lead"`) ループ・`random.randint()` 回避・総合実戦テスト |
| **第4回** | サブルーチン・絶対座標・総合試験 | `4-1` 〜 `4-6` | `def sub_a():` 再利用・複数サブルーチン役割分担・絶対方位モード (`heading`)・パーツ最適化タイムアタック・二重周回コース・修了総合試験 |

### 開発訓練（全4部・19ステージ）
課題学習で身につけた基礎を、**`4×4` 基準・1ステージ1要素のやさしい段階構成** で対人戦・SP兵装戦術へと橋渡しします。

| 部 | テーマ | ステージ / CPU | 主な学習内容 |
| :---: | :--- | :---: | :--- |
| **第1部** | 4×4 基本戦闘＆リアクション入門（60分） | St.1〜6 (`4×4`) | 索敵→照準→発砲ループ・距離制御 (`enemy_dist` 引き撃ち)・被ロック回避 (`under_lock()`)・被弾反転 (`hit_from` / `last_hit`)・壁回避回り込み・第1部卒業戦 |
| **第2部** | 6×6 戦術アルゴリズム拡張（60分） | St.7〜10 (`6×6`) | カウンタ周期回避 (`a % 20 == 0`)・乱数ジグザグ回避・HP連動フェーズ切替 (`hp_percent` → `mode`)・第2部卒業戦 |
| **第3部** | SP兵装 戦術マスター（60分） | St.11〜13 (`4×4`)<br>St.14〜16 (`6×6`) | 全6種SP兵装（誘導ミサイル `missile`・地雷 `mine`・バリア `shield`・煙幕 `smoke`・緊急ブースト `boost`・デコイ `decoy`）と発動センサー (`incoming_shell` / `under_lock` / `sp_cooldown`)・第3部卒業戦 |
| **第4部** | 【自習】特殊シャシー・多対一・卒業検定 | St.17 (`6×6`)<br>St.18〜19 (`8×8`) | 固定砲塔駆逐戦車 (`destroyer`)・1 vs 2 チーム連携戦・シールドエース相手の統合卒業検定 |

## 4. 授業運用・不正防止対策とクリアコード検証（教員向け）

### 4.1 課題学習・開発訓練における「模範解答」ロックの仕組みと解放フロー
「自力で考える機会」と「講義進行上の救済」を両立するため、**課題学習（第1回〜第4回）** と **開発訓練（第1部〜第4部）** の双方で進捗状況に応じて以下のように制御しています。

- **未クリアの課題・ステージ**: 初期状態では **`🔒 模範解答 (0/5)`** としてロックされています。以下の条件をすべて満たしたときに **`🔓 模範解答`** に切り替わります。
  1. **順次進行**: 同じ回（開発訓練では同じ部）の中で、その問題より前の問題・ステージをすべてクリアしていること（各回・各部の第1問を除く）。
  2. **ヒント確認**: 当該問題・ステージの **「ヒント」** を開いていること。
  3. **実質的な試行 5回**: 盤面に **3ブロック以上** 配置した状態で、**互いに異なる配線・パラメータ構成のまま 5回失敗**（`TRY AGAIN` 等）していること。
- **解放時の確認と閲覧後**: 解放後に「🔓 模範解答」を押すと、*「未クリア状態で模範解答を開くと、その後に盤面を変更・リセットしても提出用クリアコード上は自力クリアから除外される」*旨の確認ダイアログが表示され、承諾して読み込むと回答が入力されます。
- **すでに自力クリア済みの問題・ステージ（復習）**: 一度自力でクリアした問題・ステージは **`模範解答（復習）`** となり、ロックなしで開いて自分のプログラムと比較できます（獲得済みの自力クリア記録は減点されません）。
- **教員デモ・試遊用アンロックコード（全問題解放・記録停止モード）**: ハンバーガーメニュー最下部の「アンロックコード」欄に当日の月日 4桁（`MMDD`：例 11月19日なら `1119`）を入力して解除すると、すべての課題学習・開発訓練で「🔓 模範解答」を確認なしで即座に読み込めます。アンロック中は上部メダル欄が **`🔓 アンロック中（達成度は記録されません）`** の表示に切り替わり、クリア進捗や提出用クリアコードは一切更新されません。「アンロック解除」ボタンを押す（またはページを再読み込みする）と現在の盤面が初期状態の白紙に戻り、通常のロック状態へ復帰します。

### 4.2 抜け道・偽装への対策
学生が試みやすい回避手段に対して、以下の多層防御を組み込んでいます。

| 想定される抜け道 | 実装している防止対策 |
| :--- | :--- |
| **模範解答を開いてスマホで撮影し、盤面リセットやページ再読み込み後に手入力して自力クリアを装う** | 未クリア状態で「模範解答を読み込む」を押した瞬間に閲覧履歴（`openedModelAnswer`）をブラウザの `localStorage` へ不可逆記録します。白紙リセットや一部カスタム、リロード後にクリアしても「模範解答使用（自力外）」として計上されます。 |
| **シークレットウィンドウや他人の画面で該当問の模範解答だけ覗き見し、自分の本番環境へ丸写し入力する** | ① 同じ回（同じ部）で前の問題・ステージをクリアしていないと試行カウント自体が進まない**順次ロック**により、白紙の別環境で先の難問だけ模範解答を開くことを防いでいます。<br>② さらに 4ブロック以上の問題・ステージでは、クリア時の盤面構成（座標・チップ種別・パラメータ・矢印）が内蔵の模範解答と完全一致した場合も自動的に「模範解答使用（自力外）」と判定します。 |
| **空盤面のまま「実行スタート」を 5回連打してロックを突破する** | ヒントを開き、かつ **3ブロック以上配置した異なる構成**での失敗のみを計上します（同じ配線の連続実行は 1回分として重複除外されます）。 |
| **環境切替やコード表示・共有画面から初期状態の答えを覗き見る** | 課題学習・開発訓練の開始時・切替時は常に `START` のみの空盤面で初期化され、共有・保存モーダルにも模範解答一覧は表示されません。 |

### 4.3 提出用クリアコード（`CP1-...`）と単元メダルバッジ
課題学習の各回（`1-1`〜`1-6` 等）または開発訓練の各部（`St.1`〜`6` 等）の全課題をクリアすると、勝利画面に **59文字固定の提出用クリアコード** が表示されるとともに、画面上部のメダルバッジ（`🥉第1回` / `🥈第2回` / `🥇第3回` / `🏆第4回` および `🥉第1部`〜`🏆第4部`）が点灯します。勝利画面のコピーボタンまたは点灯中のメダルバッジをタップすると、コード単体のみがクリップボードへコピーされます。

```text
CP1-<UUID 32桁>-<暗号ブロックA 8桁>-<暗号ブロックB 8桁>-<改ざん検知署名 4桁>
```

- **暗号ブロックA（復号後 12桁 `D1`）**: 単元番号（`11`〜`14`=課題学習第1〜4回 / `21`〜`24`=開発訓練第1〜4部）・問題数・うち自力クリア数（模範解答未使用・丸写し除外）・修了月日時分
- **暗号ブロックB（復号後 12桁 `D2`）**: ゲームバージョン（`MNNPP`）・合計クリア秒数・プログラム配線指紋（`000`〜`999`）
- UUID の一部を用いた `BITXOR` 暗号化とモジュラー署名が付与されているため、他人のコードの UUID 書き換えや数値の捏造を行うと真贋判定で即座に無効と判定されます。

### 4.4 教員向け：Excel 確認シート用 復号・真贋判定関数一覧（Excel 2013 以降 / マクロ不要）

`A2` セルに学生から提出されたクリアコード（`CP1-...`）を貼り付けたとき、隣の列に以下の標準関数を入れると自動で真贋判定・復号されます（改行なしの 1行数式としてそのままコピーできます）。

| 列 | 項目 | 数式 |
| :---: | :--- | :--- |

## 5. 付属の戦車データ (`tanks/` フォルダ・全31機)

リポジトリおよびポータブル配布版の `tanks/` フォルダには、初期自機1機と対戦相手・学習用サンプル30機の計 **31種類の `.vstank.json` ファイル** が収録されています。

### 付属ファイルの読み込み・活用方法
- **対戦相手として読み込む**: 「テストグラウンド」上部の **「相手読込」** ボタン、または「共有・読込」モーダルのインポート欄から `tanks/` 内のファイルを複数選択して追加できます（通常最大8台・スマホレイアウト時最大4台まで同時対戦可）。
- **自機に読み込んで改造する**: エディタ上部の **「読込」** ボタンから開くか、「共有・読込」モーダル内の機体一覧から **「自機に読込」** をクリックすると、付属戦車の中身（配線・Pythonコード）を見てそのまま改造できます。
- ご自身が保存した `.vstank.json` ファイルも同じ `tanks/` フォルダに置いておくと、自機としても対戦相手としても共通のフォルダから管理しやすくなります。
